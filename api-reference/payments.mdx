---
title: "Payments"
description: "Create a payment using the Payments API."
---

## Endpoint

`POST /v1/payments`

## Authentication

This endpoint requires an API key and an idempotency key.

```http
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <unique-key>
```

## Request

```json
{
  "amount": 1000,
  "currency": "USD",
  "customer_id": "cus_123",
  "payment_method": {
    "type": "card",
    "token": "tok_123"
  }
}
```

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| amount | integer | Yes | Payment amount in cents |
| currency | string | Yes | Three-letter currency code |
| customer\_id | string | No | ID of the customer |
| payment\_method | object | Yes | Payment method details |
| payment\_method.type | string | Yes | Payment method type |
| payment\_method.token | string | Yes | Token for the payment method |

## Response

```json
{
  "id": "pay_123",
  "status": "processing",
  "amount": 1000,
  "currency": "USD",
  "customer_id": "cus_123",
  "payment_method": {
    "type": "card"
  },
  "created_at": "2026-08-18T10:30:00Z"
}
```

A newly created payment can return `processing`, `succeeded`, or `failed`. Most newly created card payments initially return `processing`.

## Error Responses

### 400 Bad Request

Returned when the request is malformed.

### 401 Unauthorized

Returned when the API key is invalid.

### 422 Unprocessable Entity

Returned when the request is syntactically valid but fails validation.

### 500 Internal Server Error

Returned when an unexpected server error occurs.
