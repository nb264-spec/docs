---
title: "Payments"
description: "Create a payment using the Payments API."
---

## Endpoint

`POST /v1/payments`

## Authentication

This endpoint requires an OAuth 2.0 access token and a unique idempotency key.

```http
Authorization: Bearer <access_token>
Content-Type: application/json
Idempotency-Key: <unique-key>
```

## Request

```json
{
  "amount": 1000,
  "currency": "USD",
  "customer_id": "cus_123",
  "payment_method": {
    "type": "card",
    "token": "tok_123"
  }
}
```

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `amount` | integer | Yes | Payment amount in cents |
| `currency` | string | Yes | Three-letter currency code |
| `payment_method` | object | Yes | Payment method details, including its `type` and token |
| `customer_id` | string | No | ID of the customer associated with the payment |

## Response

New card payments usually start in `processing` and later transition to `succeeded` or `failed`.

```json
{
  "id": "pay_123",
  "status": "processing",
  "amount": 1000,
  "currency": "USD",
  "customer_id": "cus_123",
  "payment_method": {
    "type": "card"
  },
  "created_at": "2026-08-18T10:30:00Z"
}
```

## Error responses

- `400 Bad Request` — the request is malformed.
- `401 Unauthorized` — the access token is missing or invalid.
- `422 Unprocessable Entity` — the request is syntactically valid but fails validation.
- `500 Internal Server Error` — an unexpected server error occurred.
